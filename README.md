# VGM MIDI DJ

Two-deck DJ webapp for performing classic video-game MIDI through hardware synths (or in-browser GM for preview). Built for an iPad live set: pick tracks, warp them to a shared tempo grid, mute outputs on the fly, beat-loop, transpose, and quantise-launch one deck against the other.

## What it does

- **Two decks** with per-deck transport, mute pills, beat loops, key transpose, and an animated piano roll.
- **Single master tempo grid.** Both decks warp to one master BPM. The master also drives a beat counter and quantises drops.
- **Track library browser** loaded from a precomputed manifest (~830 tracks). Sortable columns: title, game, BPM, key, meter, length. Filter by game; search by title.
- **Hardware mode** routes MIDI to a connected USB MIDI interface (channel-mapped to a specific synth rig).
- **Preview mode** plays everything through an in-browser GM synth (WebAudioTinySynth) using representative patches that simulate each hardware destination — so you can rehearse anywhere.
- **Mix switch** (A / A+B / B) instead of a crossfader, since MIDI cuts don't crossfade musically.

## Features

### Master transport (footer)
- Beat-count dots (1..N based on selected meter)
- Tap-tempo + reset-to-beat-1 (↻)
- Meter selector (2/4 – 8/4)
- BPM slider — single source of truth; both decks auto-warp
- First loaded track auto-anchors master BPM so nothing gets warped on launch

### Deck (×2)
- **Piano roll** — notes coloured by source channel, drum lane at the bottom. Drag to scrub (snaps to beat; hold Shift for fine scrub). Scroll to pan, ctrl/cmd/pinch to zoom. Double-click resets zoom. A faint top strip shows the visible window when zoomed.
- **Live stats** — native BPM, key, meter (with `*` if it changes), length, position.
- **Output pills** — one per hardware destination receiving signal (Juno · 2, SH-01A · 1, …). Tap to mute/unmute that output. Activity dot flashes on note hits.
- **Beat loops** — 1, 2, 4, 8, 16 beat pads. Tap to enter a loop quantised to the perceived beat. Tap the active pad once to arm a *clean exit* (loop plays to the end then continues forward). Notes that should still be ringing across the loop point get deferred noteOffs so tails don't get chopped.
- **Transpose** — `− 0 +` (±12 semitones). Skips drum channels.
- **Volume**.
- **CUE** — solos this deck (preview-style).
- **DROP** — quantised launch. Schedules this deck to start at the next master downbeat.

### Track library (browser)
- 830+ tracks across 17 games.
- Per-track metadata generated by `tools/build-manifest.js`:
  - **Perceived BPM** via inter-onset-interval histogram + octave folding into 80–160. Overrides the file's metadata tempo when it lies (Doom and Commander Keen MIDIs especially).
  - **Key** via Krumhansl-Kessler pitch-class profile correlation.
  - **Meter** from MIDI time-signature meta events; tracks with shifting meters are flagged.
  - **Channels used**, **note count**, **duration**.

## Hardware setup

| MIDI channel | Synth | Role |
|--------------|-------|------|
| 1 | Juno 106 | Pads / chords |
| 2 | SH-01A | Leads / arps |
| 3 | Bass Station 2 | Bass |
| 4 | Roland Keytar | Melody |
| 10 | TR-08 | Drums |

Signal flow:

```
iPad (Safari) → USB MIDI interface → 5 channels → synth rig
```

Drums get remapped from GM kit note numbers to the TR-08 layout automatically.

## Quick start

```sh
npm run manifest         # rebuild docs/tracks.json from docs/midi-files/
npm run serve-local      # plain HTTP at localhost:8080
npm run serve            # HTTPS at localhost:8080 (needs cert.pem/key.pem; iPad needs HTTPS for Web MIDI)
```

Open `http://localhost:8080`. Toggle **preview** in the header for in-browser GM playback; otherwise it routes to your connected MIDI interface.

## Converting SPC → MIDI (VGMTrans)

For SNES games not yet in the library (e.g. Link to the Past):

1. Get `.spc` files (rip from ROM with SPC700 Player, or download from zophar.net/snesmusic)
2. Open [VGMTrans](https://github.com/vgmtrans/vgmtrans)
3. Drag the `.spc` in → it auto-detects the N-SPC sequence
4. Right-click the collection → Convert → MIDI
5. Drop the `.mid` into `docs/midi-files/<game>/`
6. Run `npm run manifest`
7. Optional: `node tools/analyze.js <file.mid>` to inspect channel layout

## Architecture notes

- **Playback engine** is a `setTimeout`-driven event scheduler keyed off MIDI ticks. Per-deck `pitch` warps real-time scheduling so a deck plays at master BPM regardless of its file's native tempo.
- **Note tails across loop wraps** — at load time, every `noteOn` is paired with its matching `noteOff` so each carries its natural `endTick`. When a loop wraps, in-flight notes whose end is past `loop.out` get deferred `noteOff` timers rather than being cut, and those timers are cancelled if a fresh note retriggers the same pitch+output.
- **Tempo detection** — files often lie about BPM (especially old IMF→MIDI conversions). The manifest runs an inter-onset histogram on note times, finds the dominant interval, and folds it into 80–160 BPM. The result becomes `perceived_bpm` and powers loop math, the library display, and the master-warp.
- **Custom widgets** — all sliders, dropdowns, scrollbars, and the master toggle are built from scratch so the look is consistent and touch-friendly; no native form chrome anywhere.
